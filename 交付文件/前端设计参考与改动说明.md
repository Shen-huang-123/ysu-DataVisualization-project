# 奥运网站设计参考与本轮改动

本轮参考的是 GitHub 上公开项目的**设计方法**，没有复制其代码、照片、图标或标识。作品保持中文叙事与本地离线可用。

| 参考项目 | 借鉴的做法 | 本作品的原创转化 |
| --- | --- | --- |
| [Olympic Feathers](https://github.com/nbremer/olympicfeathers) | 用一个明确的视觉隐喻组织奥运数据，并把解释放在读数附近 | 首页采用四段色线与圆形编号，形成四项任务的“赛道目录”；每个入口直接写明研究问题 |
| [The Gamma Olympics Web](https://github.com/the-gamma/thegamma-olympics-web) | 从国家、项目和运动员的问题逐层进入细节 | 封面提供四个问题直达任务，保留七幕阅读路径供连续浏览 |
| [Paris Olympics Creative Website](https://github.com/atharvotech/Paris-Olympics-Creative-Website) | 大幅赛事影像与清晰的文字层级 | 沿用作品自己的奥运影像和中文主标题，通过左右分区让问题目录与封面叙事共存 |

## 具体改动

- 首页右侧新增四问目录：奖牌怎么算、谁被看见、结论能否经受反例、2028 如何变化。
- 四个入口分别直达任务一至四，圆形编号与四色赛道线形成统一的奥运识别。
- 目录只在桌面宽屏显示；较窄屏幕继续使用既有的任务直达导航。动效只用于悬停与键盘聚焦，并尊重“减少动态效果”系统设置。
- 未改动七幕滚动引擎和证据结论，避免影响已有的回退恢复与口径表述。

实现文件：根目录 `index.html` 与 `assets/olympic-editorial.css`。

## 首页穿隧动效调整（2026-11-15）

继续核查了 GitHub 上三个相关实现：[3D Scroll Tunnel](https://github.com/nawajish-k/3d-scroll-tunnel) 使用 CSS 透视与 GSAP 串联图片；[Infinite 3D Tunnel](https://github.com/satishydv/Infinite-3d-Tunnel) 使用 Three.js 与对象池绘制连续空间；[WARP](https://github.com/AmiARMiess/warp) 使用离线 Canvas 2D 光轨。它们提供技术方向，本作品没有复制任何源码或素材。

现有首页使用七张叙事影像与 GSAP 滚动进度。旧版入口位于画面右侧，隧道层透明度很低，观感更接近圆形揭幕。本轮将桌面端入口移至画面中心，增强前景与背景的缩放差，令十层轨道弧线随**每一次切幕进度**扩张，并在切幕端点自然消失。仍使用原有 DOM 和 GSAP 渲染循环；没有增加常驻 Canvas/WebGL 渲染任务。手机端保留原来的轻量影像过渡，系统“减少动态效果”继续关闭隧道层。

Edge 离线验收：1440 与 390 宽度分别抽查七幕进度 25 个点，所有点至少有一幕可见，无横向溢出；任务四跳转后回退首页成功。手机减少动画模式前三个位置无脚本错误。回退时浏览器会报告 `ViewTransition opt-in disabled`，来源为任务页在 `file://` 下启用的页面转场；实测跳转与回退仍可用。

## 星空路径版首页（2026-11-15）

根据用户反馈删除了重复的四问探索卡。现用离线 Canvas 星点、透视轨道和 SVG 藤蔓形路径串起七幕。滚轮推进时星点向外移动，路径轻微上行，章节影像沿路径两侧逐步显露；原有任务直达与章节刻度仍可随时跳转。所有运动由既有 GSAP 滚动进度驱动，没有独立持续播放的动画循环。手机展示低透明度的整幅影像，减少动画模式静态显示。

这是一种轻量的空间视觉设计，仍使用二维图层；若以后需要真正进入可自由转向的三维隧道，需要重新制作 WebGL 场景与镜头、另做性能和移动端验收。

## 真实透视隧道与闲置巡游（2026-11-15）

用户指出上一版的两个问题：星空只是平面背景，七幕在切幕时有重叠。本轮参考 [Infinite 3D Tunnel](https://github.com/satishydv/Infinite-3d-Tunnel) 的程序化空间思路，用 [Three.js](https://github.com/mrdoob/three.js) 自行生成三维环、沿隧道延伸的曲线和星点，并让透视相机沿 Z 轴随滚动前进。没有直接使用网上现成模型：作品需要每次滚动都能精确定位镜头，程序化几何可离线运行、双向倒滚、文件体积可控，也避免来源不明的模型版权问题。Three.js 0.159.0 已作为本地依赖存于 `assets/three.min.js`，许可证见 `assets/THREE-LICENSE.txt`。

七幕改为分段切换：上一幕先退出，短暂露出完整隧道，下一幕再进入。同一时刻最多一幕正文处于可读状态。闲置 9 秒自动走向下一幕，之后每 6.5 秒继续一幕；滚轮、触摸、点击和按键会重置闲置计时，底部“自动巡游”按钮可关闭。到终章后自动沿章节反向巡游。系统减少动画模式关闭 3D 与自动播放；设备没有 WebGL 时回退到本地 Canvas 2D 星空。

本地 Edge 检查：1440/390 宽 WebGL 可用且无脚本错误或横向溢出；1440 宽 49 个切幕进度点同时可见的正文最多一幕；闲置 10 秒进入第二幕，按钮关闭后不再继续；禁用 WebGL 时二维回退可用。

## 三维巡游流畅性修正（2026-11-15）

根据实际观察，上一版用浏览器原生 `smooth` 跳到下一幕，观看时像瞬间切换；二维藤蔓和三维隧道同时出现也不协调。本轮删除二维藤蔓，去除在文字前方横穿的长螺旋线，保留三维环与星点；赛事影像改为统一的椭圆记忆窗口，并在正文一侧压暗光轨。

闲置自动巡游现在使用 GSAP 将滚动位置在 4.8 秒内连续推进一幕，每 10.5 秒再走一幕；用户滚轮、触摸、点击或按键会立即终止当前巡游，再等待 9 秒。系统减少动画模式继续停用自动巡游。Edge 验收分别在 1440、1024、390 及手机减少动画模式下抽查七幕各49个进度点；最多一幕正文可见，未见脚本错误或横向溢出。自动巡游连续采样的滚动位置由 2→54→238→433→645→884→900，真实滚轮中断后 1.5 秒内位置保持不变。

## 镜头节奏与影像衔接精修

参考 [Codrops 的 Blender 路径画廊](https://tympanus.net/codrops/2026/07/07/building-a-scroll-driven-3d-gallery-using-a-blender-camera-path-with-three-js-and-gsap/) 和 [电影式滚动体验](https://tympanus.net/codrops/2025/11/19/how-to-build-cinematic-3d-scroll-experiences-with-gsap/) 的镜头路径与叙事同步方法：首页镜头现在在章节前后减速停留，只在转场中段推进；影像沿左右空间方向以轻微透视进入，退出时收向空间深处，避免在镜头前放大遮挡。辅助文字减弱对比，主标题和进入按钮保留视觉重点。没有复制参考项目代码或素材。
